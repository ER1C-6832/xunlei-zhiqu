# 二、E0 总体架构决策

## 2.1 生产主形态

生产主线采用：

```text
浏览器 Extension
        │
        │ 本地扫描 / 框选 / 自动发现
        ▼
ZhiquServiceClient
        │
        ▼
迅雷客户端内置 Runtime
        │
        ├── Agent Core
        ├── ResourceJob
        ├── Diagnosis / Recovery
        ├── Node A / Node B Orchestration
        │
        ├── ModelGatewayPort
        │       │
        │       ▼
        │  迅雷 AI Gateway
        │       │
        │   Model Router
        │
        └── DownloadExecutorPort
                │
                ▼
           迅雷真实下载引擎
```

核心判断：

> **完整 ResourceDelivery Agent 的长期任务主体位于迅雷客户端 Runtime。**

---

## 2.2 云端 fallback 不复制完整 Runtime

无客户端时允许：

```text
Extension
   │
   ▼
CloudAnalysisTransport
   │
   ▼
迅雷 Cloud Analysis Service
   │
   ▼
迅雷 AI Gateway
```

Cloud Analysis 只负责：

```text
Sanitized Analysis Request
→ Node A
→ ResourcePlan
```

不要在云端复制：

```text
本地 ResourceJob 状态机
本地磁盘
本地下载进度
Download Engine
暂停 / 恢复
本地诊断
本地一键续取状态
```

原因：

完整 ResourceJob、下载状态、文件系统和恢复状态最终属于迅雷客户端。

禁止在 E0 中实现一个第二套完整“Cloud Runtime”。

# E0.1：建立 ZhiquServiceClient，去掉 Extension 的部署耦合

当前 Extension 中仍存在大量类似：

```ts
fetch(`${RUNTIME_URL}/v1/capture/analyze`)
fetch(`${RUNTIME_URL}/v1/jobs`)
chrome.tabs.create({
  url: `${RUNTIME_URL}/app/...`
})
```

这属于部署细节泄漏到 UI / product logic。

建立一个统一客户端层，例如：

```text
apps/extension/src/services/
    zhiquServiceClient.ts
    transports/
        localHttpTransport.ts
```

名称可调整。

目标接口可以类似：

```ts
interface ZhiquServiceClient {
  getCapabilities(): Promise<ZhiquCapabilities>

  analyzeResources(
    request: AnalyzeResourcesRequest
  ): Promise<ResourcePlan>

  createJob(
    request: ResourceJobCreateRequest
  ): Promise<ResourceJobSnapshot>

  favoriteResource(...): Promise<...>

  openTaskCenter(...): Promise<void>
}
```

不要让 React 组件直接拼：

```text
/v1/*
```

不要让 React 组件直接知道：

```text
http://127.0.0.1:8765
```

StageDApp 等 UI 只调用：

```text
zhiquService.analyzeResources(...)
zhiquService.createJob(...)
zhiquService.openTaskCenter(...)
```

### Runtime URL

当前 `VITE_RUNTIME_URL` 可以继续作为 Demo transport 配置。

但它只能存在于：

```text
LocalHttpTransport
```

内部。

不要再通过 Vite plugin 对多个业务文件进行：

```text
const RUNTIME_URL = ...
```

字符串替换。

可以保留一个统一配置入口：

```ts
getRuntimeEndpoint()
```

但产品组件不直接使用。

# E0.2：建立 Capability Resolver，不要只有 Endpoint Resolver

不要设计成：

```text
现在 Runtime URL 是什么？
```

而应该设计为：

```text
现在有哪些能力？
```

定义轻量：

```ts
type ZhiquCapabilities = {
  localDiscovery: true
  intelligentAnalysis: boolean
  localDownload: boolean
  cloudDelivery: boolean
  reacquisition: boolean
  runtimeKind:
    | 'demo_local'
    | 'client'
    | 'cloud_analysis'
    | 'none'
}
```

字段名不强制。

核心语义必须保留。

Future resolver：

```text
检测迅雷客户端 Runtime
        │
       有
        ▼
CLIENT_RUNTIME

没有客户端
        │
        ├── 有迅雷登录/Guest AI Credential
        │       ▼
        │   CLOUD_ANALYSIS
        │
        └── 无
                ▼
             LOCAL_ONLY
```

E0 当前不需要真的检测迅雷客户端。

可以：

```text
环境变量 / fixture capability
```

模拟不同形态。

但业务 UI 必须开始根据 capability，而不是 localhost 地址做决策。

# E0.4：为无客户端分析建立 CloudAnalysisRequest 隐私边界

这是一个非常重要的架构修正。

当前本地链路：

```text
Extension
→ CaptureBatch
→ Local Runtime
→ EvidenceBuilder
→ EvidenceReducer
→ Sanitized Evidence
→ Model
```

安全。

但未来禁止简单：

```text
Extension
→ 原始 CaptureBatch
→ https://cloud-runtime
```

因为 CaptureBatch 可能包含：

```text
真实资源 URL
页面 URL
临时 Token
Query Credential
未来 Cookie/Header 信息
```

因此建立一个显式的：

```text
CloudAnalysisRequest
```

或：

```text
SanitizedAnalysisRequest
```

这是独立于 CaptureBatch 的契约。

Extension-side cloud sanitizer 至少保证：

```text
禁止上传：
- 完整真实下载 URL
- Cookie
- Authorization
- 临时 Token
- 本地文件路径
- 完整页面 HTML
- 与候选无关的整页正文
```

可以上传：

```text
candidate_id
display_name
filename
extension
anchor_text
必要 nearby_text
section_heading
公开 MIME / size / media metadata
resource family hint
selection context
公开页面标题
必要设备兼容信息
```

不要把 Python EvidenceReducer 整套复制到 Extension。

Extension cloud sanitizer 只负责：

> **隐私边界。**

真正 Token reduction、grouping、Prompt compiler 未来仍可以在：

```text
Cloud Analysis Service
```

完成。

当前 Demo 不需要真实访问云端，但：

```text
CloudAnalysisTransport
```

可以使用 fixture/mock endpoint 验证数据中不存在 URL / credential。

# E0.7：冻结 DownloadExecutorPort

真实下载尚未开始。

但 Stage E 开始前先建立接口。

Runtime 内定义：

```python
class DownloadExecutorPort(Protocol):
    async def create(...)
    async def pause(...)
    async def resume(...)
    async def cancel(...)
    async def status(...)
    async def add_source(...)
```

具体参数可结合现有 ResourceJob 调整。

原则：

```text
Agent / JobController
→ DownloadExecutorPort
```

禁止：

```text
Agent
→ httpx download implementation
```

Stage E：

```text
DemoHttpDownloadExecutor
implements DownloadExecutorPort
```

未来：

```text
XunleiDownloadExecutor
implements DownloadExecutorPort
```

Agent、Diagnosis、Recovery 不需要因此重写。

### 此步骤不要做

- 不实际下载文件；
- 不实现 Range；
- 不实现 aria2；
- 不实现 BT；
- 不实现 SQLite。

只建立最小 Port 和一个：

```text
Noop / Fixture Executor
```

确保现有 ResourceJob 仍正常工作。

# E0.14：只做无损 / 低风险输入压缩

检查 Pipeline wire。

### A. display_name / filename / anchor_text

如果规范化后完全相同：

```text
display_name == filename
```

不要重复发送。

如果：

```text
anchor_text == display_name
```

也不要重复。

需要在 wire 协议中规定：

> 缺失字段不表示未知；若可由其他同义字段恢复，则 Runtime 可省略重复值。

不要修改 canonical EvidencePack。

只优化 model-facing wire。

---

## B. Selection IDs

如果：

```text
selection.candidate_ids
```

等于当前所有 AI candidate ids：

```text
省略
```

在 system protocol 中说明：

> absence in full-page / automatic mode means all provided candidates are in analysis scope.

只有：

```text
rectangle / explicit partial selection
```

才保留。

---

## C. section_heading 去重

当前 nearby_text 已支持 context ref。

对大量重复：

```text
section_heading
```

做同样的共享引用或 group-level heading。

例如：

```text
Windows
Windows
Windows
Windows
```

不要重复四次。

---

## D. technical_metadata alias

仅对 Model-facing wire 的高频 key 使用短 alias。

例如可以考虑：

```text
resource_family_hint
content_type
content_length
network_observed
media_kind
attachment_kind
```

映射成短 key。

必须在 system protocol 中清楚定义。

Canonical model 和 Runtime 内部仍使用完整字段名。

不要把所有 metadata 都压成难维护的单字母。

只压高频、稳定字段。

## D. recommendations 尝试确定性派生

```text

→ selected
```

```text

```

生成：

```text

```

canonical ResourcePlan 中仍然保留 recommendations。

但不一定由 LLM 生成。

如果真实页面证明模型 recommendation 包含额外有价值信息，再保留。

不要为了 Token 强行删除产品价值。

# 二十一、最终原则

```text

→ localhost FastAPI Runtime
→ Demo Task Center
```

```text
真实进度
```

不要提前跨入 Stage F。
